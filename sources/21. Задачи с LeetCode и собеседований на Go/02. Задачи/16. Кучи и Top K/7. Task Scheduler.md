## Жадное планирование: CPU и время простоя

В предыдущих задачах мы использовали кучи для работы с потоками данных или агрегации. Но кучи также являются сердцем любого **Планировщика (Scheduler)** — от операционных систем (Linux CFS) до рантайма Go.

Задача **Task Scheduler** (LeetCode №621) моделирует работу процессора, который должен выполнить набор задач с учетом ограничений на охлаждение (охлаждение здесь — это метафора зависимости или задержки).

**Условие:** Дан массив символов `tasks`, представляющий задачи (например, 'A', 'B'), и целое число `n` (время охлаждения). Между двумя одинаковыми задачами должен быть перерыв как минимум в `n` единиц времени. В это время процессор может либо выполнять другую задачу, либо простаивать (`idle`). 
Нужно найти **минимальное количество единиц времени**, необходимое для выполнения всех задач.

---

## Стратегия: Жадный подход (Greedy)

Чтобы минимизировать время, нам нужно как можно реже допускать простой процессора (`idle`). 
**Интуиция:** Самые часто встречающиеся задачи — это наши главные враги, так как именно они создают больше всего обязательных пауз. Значит, их нужно выполнять **как можно раньше**, чтобы "разбавить" их другими задачами в промежутках.

### Почему здесь нужна Куча?
Нам нужно на каждом шаге выбирать задачу, которой осталось выполнить больше всего. После выполнения задачи её частота уменьшается, и нам снова нужно найти текущий максимум. Динамический поиск максимума — это работа для **Max-Heap**.

---

## Алгоритм с использованием Max-Heap и Очереди

1. **Подсчет:** Считаем частоту каждой задачи (например, 'A': 3, 'B': 3).
2. **Инициализация:** Кладем все частоты в Max-Heap.
3. **Цикл планирования:**
   - Извлекаем самую частую задачу из кучи.
   - Выполняем её (уменьшаем счетчик).
   - Мы не можем вернуть её в кучу сразу из-за `n`. Помещаем её в **очередь ожидания** вместе с временем, когда она снова станет доступна.
   - На каждом тике времени проверяем очередь: если время "заморозки" задачи вышло, возвращаем её в Max-Heap.
```mermaid

    B --> C["Очередь ожидания:<br>Задачи на охлаждении n"]
```

### Идиоматичная реализация на Go

```go
import (
    "container/heap"
)

// 1. Стандартный Max-Heap для частот
type MaxHeap []int
func (h MaxHeap) Len() int           { return len(h) }
func (h MaxHeap) Less(i, j int) bool { return h[i] > h[j] } // Max-Heap
func (h MaxHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MaxHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *MaxHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[0 : n-1]
    return x
}

type TaskInfo struct {
    count     int
    readyTime int
}

func leastInterval(tasks []byte, n int) int {
    if n == 0 {
        return len(tasks)
    }

    // Шаг 1: Считаем частоты
    freq := make(map[byte]int)
    for _, t := range tasks {
        freq[t]++
    }

    // Шаг 2: Добавляем в кучу только частоты
    h := &MaxHeap{}
    for _, count := range freq {
        heap.Push(h, count)
    }

    time := 0
    queue := []TaskInfo{} // Очередь для задач на кулдауне

    for h.Len() > 0 || len(queue) > 0 {
        time++

        if h.Len() > 0 {
            // Берем самую приоритетную (частую) задачу
            count := heap.Pop(h).(int) - 1
            if count > 0 {
                // Если задача не закончилась, отправляем в очередь ожидания
                queue = append(queue, TaskInfo{count, time + n})
            }
        }

        // Если пришло время, возвращаем задачу из очереди в кучу
        if len(queue) > 0 && queue[0].readyTime == time {
            heap.Push(h, queue[0].count)
            queue = queue[1:]
        }
    }

    return time
}
```

## Математический подход (Senior Level)

На собеседовании в топ-тех компании интервьюер может спросить: *"Можно ли решить это без симуляции, за $O(N)$?"*.
Да. Мы можем вычислить "пустоты".

1. Найдем максимальную частоту `f_max` (например, задача 'A' встречается 3 раза).
2. Количество самых частых задач `n_max` (например, если 'A' и 'B' оба встречаются по 3 раза).
3. Минимальное время определяется формулой:
   $$(f\_max - 1) * (n + 1) + n\_max$$
   Это блоки, разделенные паузами, плюс последние задачи в финальном блоке.
4. Ответ — это максимум между этой формулой и общей длиной `len(tasks)`.
```go
func leastIntervalMath(tasks []byte, n int) int {
    freq := make([]int, 26)
    maxFreq := 0
    for _, t := range tasks {
        freq[t-'A']++
        if freq[t-'A'] > maxFreq {
            maxFreq = freq[t-'A']
        }
    }

    maxCount := 0
    for _, f := range freq {
        if f == maxFreq {
            maxCount++
        }
    }

    ans := (maxFreq-1)*(n+1) + maxCount
    if ans < len(tasks) {
        return len(tasks)
    }
    return ans
}
```

### Оценка и сравнение:
- **Симуляция с кучей:** $O(T \log 26)$, где $T$ — общее время. Логически повторяет работу реальных планировщиков, легко расширяется (например, если у задач разные приоритеты).
- **Математика:** $O(N)$ по времени, $O(1)$ по памяти. Идеально, если нужно просто число, но не подходит для генерации самой последовательности задач.
