## Баланс двух сил: Динамический поиск медианы

В предыдущих задачах мы использовали одну кучу для извлечения экстремумов (минимумов или максимумов). Однако существуют задачи, где нам нужно постоянно находиться «в центре» данных. Задача **Find Median from Data Stream** (LeetCode №295) — это классика системного проектирования алгоритмов, которая встречается в задачах мониторинга (вычисление 50-го перцентиля задержек/latency в реальном времени) и в статистическом анализе потоковых данных.

**Условие:** Реализуйте структуру данных `MedianFinder`, которая поддерживает:

1. `addNum(num)` — добавление целого числа из потока в структуру.
2. `findMedian()` — возврат медианы всех добавленных на данный момент элементов.

Медиана — это среднее значение в отсортированном списке. Если размер списка нечетный, медиана — это средний элемент. Если четный — это среднее арифметическое двух средних элементов.

---

## Архитектурный вызов: Почему сортировка — это провал

Наивный подход подразумевает хранение всех чисел в слайсе и их сортировку при каждом вызове `findMedian()`.

- **Добавление:** $O(1)$.
- **Поиск медианы:** $O(N \log N)$.

Даже если использовать `Binary Search` для вставки элемента в уже отсортированный массив (вставка за $O(N)$ из-за сдвига элементов), суммарная сложность для $N$ чисел составит $O(N^2)$. Для высоконагруженной системы мониторинга, обрабатывающей тысячи запросов в секунду, это неприемлемо. Нам нужно решение, которое обеспечивает логарифмическое время добавления и константное время получения медианы.

---

## Решение: Две кучи (Two Heaps Pattern)

Для эффективного поиска медианы мы разделим все входящие данные на две равные (или почти равные) половины:

1. **Левая половина (Small Numbers):** Здесь мы храним меньшую часть чисел. Нам нужно быстро получать _самое большое_ число из этой половины. Для этого идеально подходит **Max-Heap**.
2. **Правая половина (Large Numbers):** Здесь мы храним большую часть чисел. Нам нужно быстро получать _самое маленькое_ число из этой половины. Для этого используем **Min-Heap**.

### Алгоритм балансировки:

Чтобы медиана всегда была "под рукой", мы должны поддерживать два инварианта:

1. Любой элемент в Max-Heap меньше или равен любому элементу в Min-Heap.
2. Разница в размере между кучами не превышает 1 элемента.

**Логика `addNum(num)`:**

1. Сначала всегда добавляем число в `Max-Heap`.
2. Так как это число могло оказаться слишком большим для левой половины, мы извлекаем максимум из `Max-Heap` и перекладываем его в `Min-Heap`.
3. Если после этого `Min-Heap` стал больше, чем `Max-Heap`, мы перекладываем самый маленький элемент из `Min-Heap` обратно в `Max-Heap`.

Этот "танец" элементов гарантирует, что `Max-Heap` всегда либо равен по размеру `Min-Heap`, либо на 1 элемент больше.

## Идиоматичная реализация на Go

Для реализации мы воспользуемся стандартным пакетом `container/heap`. Поскольку нам нужны и Min-Heap, и Max-Heap, мы создадим универсальную структуру.

```go
import (
    "container/heap"
)

// 1. Реализация базовой кучи
type IntHeap struct {
    arr    []int
    isMax  bool // Флаг для переключения между Min и Max логикой
}

func (h IntHeap) Len() int { return len(h) }
func (h IntHeap) Swap(i, j int) { h[i], h[j] = h[j], h[i] }
func (h IntHeap) Less(i, j int) bool {
    if h.isMax {
        return h.arr[i] > h.arr[j] // Логика Max-Heap
    }
    return h.arr[i] < h.arr[j] // Логика Min-Heap
}

func (h *IntHeap) Push(x any) {
    h.arr = append(h.arr, x.(int))
}

func (h *IntHeap) Pop() any {
    old := h.arr
    n := len(old)
    x := old[n-1]
    h.arr = old[0 : n-1]
    return x
}

// 2. Основная структура MedianFinder
type MedianFinder struct {
    small *IntHeap // Max-Heap для левой половины
    large *IntHeap // Min-Heap для правой половины
}

func Constructor() MedianFinder {
    s := &IntHeap{isMax: true}
    l := &IntHeap{isMax: false}
    heap.Init(s)
    heap.Init(l)
    return MedianFinder{small: s, large: l}
}

func (this *MedianFinder) AddNum(num int) {
    // Шаг 1: Добавляем в левую половину (Max-Heap)
    heap.Push(this.small, num)
    
    // Шаг 2: Балансируем — самый большой из левых должен уйти в правые
    heap.Push(this.large, heap.Pop(this.small))
    
    // Шаг 3: Поддерживаем инвариант размера (small >= large)
    if this.large.Len() > this.small.Len() {
        heap.Push(this.small, heap.Pop(this.large))
    }
}

func (this *MedianFinder) FindMedian() float64 {
    if this.small.Len() > this.large.Len() {
        // Если чисел нечетное количество, медиана на вершине Max-Heap
        return float64(this.small.arr[0])
    }
    // Если четное — среднее арифметическое вершин двух куч
    return float64(this.small.arr[0]+this.large.arr[0]) / 2.0
}
```

## Анализ и Mechanical Sympathy

### Сложность:

- **Добавление (`AddNum`):** $O(\log N)$. Мы совершаем константное количество операций `Push` и `Pop` в кучи.
- **Поиск медианы (`FindMedian`):** $O(1)$. Мы просто обращаемся к корневым элементам слайсов (`arr[0]`).
- **Память:** $O(N)$ для хранения всех чисел в двух кучах.

### Почему это эффективно в Go?

1. **Утилизация кэша:** Кучи реализованы на базе плоских слайсов. Корни куч (`small.arr[0]` и `large.arr[0]`) почти всегда находятся в L1-кэше процессора, так как к ним идет постоянное обращение.
2. **Отсутствие аллокаций:** После того как слайсы внутри куч вырастут до достаточного размера, новые вызовы `AddNum` перестанут вызывать аллокации в куче (heap allocation), если не происходит превышения `capacity`.
3. **Потоковая обработка:** Эта структура идеально подходит для систем, где данные поступают непрерывно. Нам не нужно знать общее количество элементов $N$ заранее.

### Инженерные нюансы (Follow-ups):

1. **Если 99% чисел в диапазоне [0, 100]?** В этом случае вместо куч можно использовать массив частот (Bucket Sort логика). Мы просто инкрементируем счетчик для каждого числа и ищем медиану, проходя по массиву. Это даст $O(1)$ на вставку и $O(1)$ на поиск медианы (так как размер массива фиксирован и мал).
2. **Если 1% чисел выходит за границы [0, 100]?** Можно использовать комбинацию: массив для чисел [0, 100] и две кучи для "выбросов" (outliers) слева и справа.
