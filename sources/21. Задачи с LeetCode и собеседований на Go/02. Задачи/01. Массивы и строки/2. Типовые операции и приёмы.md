
Теоретическая база из статьи [[1. Теория. Массивы и строки]] дала вам понимание внутреннего устройства массивов, слайсов и строк в Go. Но в реальной задаче знание того, как устроен `SliceHeader` или почему `string` иммутабельна, — это лишь половина успеха. Вторая половина — это умение мгновенно применить правильный приём: пройти массив двумя указателями, построить префиксные суммы, за O(N) найти окно с нужным свойством или без дополнительной памяти модифицировать слайс in-place.

В этой статье мы формализуем **семь фундаментальных операционных приёмов**, которые закрывают 90% задач кластера «Массивы и строки» и служат кирпичиками для более сложных паттернов. Каждый приём разобран с идиоматичным Go-кодом, анализом механической симпатии и указанием ловушек. Это не просто справочник — это карта, которая позволит вам, взглянув на условие задачи, мгновенно выбрать нужный инструмент.

### Приём 1: Идиоматичный обход и базовые манипуляции

Прежде чем переходить к сложным паттернам, зафиксируем «гигиенический минимум» — операции, которые Senior Go-разработчик выполняет на автомате, без оглядки на IDE.

**Обход слайса.** Используйте `range` всегда, когда не нужна прямая работа с индексом ради модификации нижележащего массива. Если требуется индекс и значение — `for i, v := range s`. Если только индекс — `for i := range s`. Цикл в стиле C (`for i := 0; i < len(s); i++`) оправдан только при нетривиальной логике изменения индекса (например, пропуск элементов).

**Обход строки.** Если задача гарантирует ASCII — индексация по байту (`s[i]`). Если Unicode — `for _, r := range s` для получения рун или явное преобразование в `[]rune` для произвольного доступа. Всегда уточняйте алфавит на старте собеседования.

**Копирование.** Для создания независимой копии слайса используйте `make` + `copy`:
```go
cp := make([]int, len(original))
copy(cp, original)
```
Это предотвращает непреднамеренное разделение нижележащего массива. Для строк копирование не требуется, они иммутабельны.

**Сравнение.** Слайсы сравнивают только с `nil`. Массивы (`[5]int`) сравнимы поэлементно оператором `==`, если их элементы сравнимы. Это ключевой мотиватор использовать массивы фиксированного размера для словарей частот: `[26]int` можно сравнить мгновенно, `map[byte]int` — только вручную.

> [!warning] Ловушка / Gotcha
> Слайс `nil` и пустой слайс `[]int{}` ведут себя одинаково в `len`, `cap`, `range`, `append`. Но `nil`-слайс сериализуется в JSON как `null`, пустой — как `[]`. В алгоритмических задачах это редко имеет значение, но Senior знает разницу и при необходимости уточняет: «Вернуть `nil` или пустой слайс?».

### Приём 2: Два указателя (Two Pointers)

Семейство приёмов, где два индекса движутся по слайсу в определённых направлениях, сокращая пространство поиска на каждом шаге.

**Встречные указатели (Opposite Direction).** Применяется в отсортированных массивах: поиск пары с суммой, проверка палиндрома, контейнер с водой. Левый указатель начинает с 0, правый — с `len-1`. На каждом шаге по монотонному условию сдвигаем один из них.

```go
// Two Sum II - Input Array Is Sorted
func twoSum(numbers []int, target int) []int {
    left, right := 0, len(numbers)-1
    for left < right {
        sum := numbers[left] + numbers[right]
        switch {
        case sum == target:
            return []int{left + 1, right + 1}
        case sum < target:
            left++
        default:
            right--
        }
    }
    return nil
}
```

**Однонаправленные указатели (Fast & Slow).** Применяется для удаления дубликатов in-place, перемещения нулей, задач на связные списки. Медленный указатель (`write`) фиксирует позицию для записи, быстрый (`read`) сканирует массив.

```go
// Move Zeroes — сохраняем порядок ненулевых элементов
func moveZeroes(nums []int) {
    write := 0
    for read := 0; read < len(nums); read++ {
        if nums[read] != 0 {
            nums[write], nums[read] = nums[read], nums[write]
            write++
        }
    }
}
```

**Механическая симпатия:** Оба варианта работают in-place, O(1) дополнительной памяти. Доступ к элементам последовательный, prefetcher CPU легко предсказывает паттерн, cache miss минимальны. Это самые «лёгкие» алгоритмы с точки зрения железа.

### Приём 3: Скользящее окно (Sliding Window)

Для задач на непрерывные подмассивы или подстроки с условием, допускающим инкрементальный пересчёт. Окно `[left, right)` расширяется вправо, при нарушении условия сжимается слева.

**Инвариант:** окно всегда удовлетворяет условию (или находится в процессе расширения), а метрика окна (сумма, частоты, количество уникальных) пересчитывается за O(1) при каждом сдвиге.

```go
// Minimum Size Subarray Sum — минимальная длина подмассива с суммой ≥ target
func minSubArrayLen(target int, nums []int) int {
    left, sum, minLen := 0, 0, math.MaxInt
    for right := 0; right < len(nums); right++ {
        sum += nums[right]
        for sum >= target {
            if right-left+1 < minLen {
                minLen = right - left + 1
            }
            sum -= nums[left]
            left++
        }
    }
    if minLen == math.MaxInt {
        return 0
    }
    return minLen
}
```

**Вариация: окно с частотным словарём.** Если условие — «содержит все символы строки t», вместо `sum` поддерживаем массив `[128]int` или `map[byte]int` с инкрементальным обновлением счётчика совпадений. При расширении символ добавляется, при сжатии — удаляется. Подробно разобрано в [[14. Разбор задачи от условия до кода]].

**Ловушка чисел с разными знаками.** Скользящее окно работает для монотонных условий (расширение окна всегда увеличивает сумму, количество символов). Если в массиве есть отрицательные числа, сумма не монотонна, и окно неприменимо — используйте префиксные суммы с хеш-картой.

### Приём 4: Префиксные суммы (Prefix Sums)

Инструмент для быстрых запросов суммы на любом подмассиве. Строим массив `pref[i+1] = pref[i] + nums[i]`, тогда сумма `nums[L:R] = pref[R] - pref[L]` (полуинтервалы). Построение — O(N), запрос — O(1).

```go
nums := []int{1, 2, 3, 4, 5}
pref := make([]int, len(nums)+1)
for i, v := range nums {
    pref[i+1] = pref[i] + v
}
// сумма [1:4] = nums[1] + nums[2] + nums[3] = 2+3+4 = 9
sum := pref[4] - pref[1] // 10 - 1 = 9
```

**Применение для подмассивов с суммой K.** Если массив содержит отрицательные числа, скользящее окно не работает. Но задача «количество подмассивов с суммой K» (LeetCode 560) решается через префиксные суммы и map: `pref[R] - pref[L] = K` → `pref[L] = pref[R] - K`. Проходим массив, поддерживаем map встреченных префиксных сумм.

```go
func subarraySum(nums []int, k int) int {
    count, sum := 0, 0
    freq := map[int]int{0: 1}
    for _, v := range nums {
        sum += v
        count += freq[sum-k]
        freq[sum]++
    }
    return count
}
```

**Go-нюанс:** Если диапазон сумм известен и невелик, массив вместо map. Для Negative/Positive в общем случае — map с предвыделением `make(map[int]int, len(nums))`.

### Приём 5: Частотный анализ — выбор между map и массивом

Огромный пласт задач: анаграммы, первый уникальный символ, пересечение массивов, группировка. Ключевой выбор — структура словаря.

**Когда массив:** алфавит известен и мал. `[26]int` для a-z, `[128]int` для ASCII. Массив даёт:
- Стековую аллокацию (нет GC).
- Доступ по индексу за 1–2 такта (прямая адресация).
- Сравнение `==` за O(размер массива), что для 26 элементов — ничтожно.

**Когда map:** ключи не ограничены диапазоном, или диапазон велик (Unicode). Map даёт O(1) в среднем, но с накладными расходами на хеширование и pointer chasing. Всегда инициализируйте через `make(map[K]V, capacity)`.

**Пример: Valid Anagram.** Подсчёт частот двумя массивами `[26]int` и сравнение `==` — эталонное решение.

```go
func isAnagram(s string, t string) bool {
    if len(s) != len(t) {
        return false
    }
    var freq [26]int
    for i := 0; i < len(s); i++ {
        freq[s[i]-'a']++
        freq[t[i]-'a']--
    }
    return freq == [26]int{} // сравнение с нулевым массивом
}
```

> [!info] Под капотом
> Сравнение массивов `[26]int` происходит поэлементно, но для 26 восьмибайтовых элементов это ~208 байт, которые помещаются в несколько кэш-линий. На практике это быстрее, чем пробег по map с хешированием, даже для одноразовой проверки.

### Приём 6: Строковые операции и преобразования

**Байты vs руны.** Если задача не гарантирует ASCII, и вы используете `len(s)` или `s[i]`, помните: вы работаете с байтами. Для посимвольных операций с Unicode преобразуйте в `[]rune`:

```go
runes := []rune(s)
for i, j := 0, len(runes)-1; i < j; i, j = i+1, j-1 {
    runes[i], runes[j] = runes[j], runes[i]
}
return string(runes)
```

**Иммутабельность и `strings.Builder`.** Конкатенация в цикле — квадратичный рост памяти. Для аккумуляции строк используйте `strings.Builder`:

```go
var b strings.Builder
for _, word := range words {
    b.WriteString(word)
}
result := b.String()
```

**Срезы строк.** `s[start:end]` не копирует данные — это O(1). Удобно для возврата подстроки без лишних аллокаций. Но будьте осторожны: если исходная строка огромна, а срез маленький и долгоживущий, память под всю строку не будет освобождена. В DSA-задачах этим обычно пренебрегают, но Senior упомянет.

### Приём 7: In-place модификации и развороты

Многие задачи требуют трансформации массива без дополнительной памяти. Базовые кирпичики:

**Разворот слайса (Reverse):**
```go
for i, j := 0, len(s)-1; i < j; i, j = i+1, j-1 {
    s[i], s[j] = s[j], s[i]
}
```

**Циклический сдвиг (Rotate):** Три разворота. `rotate(nums, k)`:
```go
k %= len(nums)
reverse(nums[:len(nums)-k])
reverse(nums[len(nums)-k:])
reverse(nums)
```

**Удаление элемента по индексу (не сохраняя порядок):**
```go
s[i] = s[len(s)-1]
s = s[:len(s)-1]
```

**Удаление элемента с сохранением порядка:**
```go
s = append(s[:i], s[i+1:]...)
```

> [!warning] Ловушка / Gotcha
> `append(s[:i], s[i+1:]...)` модифицирует нижележащий массив. Если после этого есть другие ссылки на исходный слайс, они увидят изменённые данные. Для изолированной работы делайте копию.

### Приём 8: Сортировка как подготовка

Сортировка — это O(N log N), и в Go она реализована в `sort` пакете. `sort.Ints`, `sort.Strings` работают in-place. Для слайсов произвольных типов — `sort.Slice` с замыканием. Но помните: замыкание может не быть встроено компилятором и вносить накладные расходы. Для performance-critical участков лучше реализовать `sort.Interface`.

**Бинарный поиск:** `sort.Search(n int, fn func(int) bool) int` — возвращает первый индекс, для которого `fn` возвращает `true`. Это обобщённый бинарный поиск, используемый как для поиска элемента, так и для «поиска по ответу».

```go
// Поиск вставки: первый индекс, где nums[i] >= target
idx := sort.Search(len(nums), func(i int) bool {
    return nums[i] >= target
})
```

**Применение в задачах:** Three Sum, Merge Intervals, поиск пар в неотсортированных массивах. Сортировка — часто первый шаг, после которого применимы два указателя или бинарный поиск.

### Интеграция приёмов: как это выглядит в реальной задаче

В одной задаче редко используется ровно один приём. Senior видит композицию. Например, задача «Product of Array Except Self» ([[6. Product of Array Except Self]]): два прохода — слева направо и справа налево — с аккумуляцией префиксных и суффиксных произведений в результирующем массиве. Это гибрид префиксных сумм (только умножение) и двух указателей (разнесённых во времени).

Задача «Merge Sorted Array» ([[9. Merge Sorted Array]]): заполнение с конца, три указателя (два на концы сливаемых массивов, один на конец результирующего). Это тот же приём «два указателя», но применённый в нестандартном порядке — справа налево.

Именно умение комбинировать отличает решателя задач от инженера, и мы будем практиковать это во всех последующих разборах.
