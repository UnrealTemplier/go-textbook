## Введение: Биты — фундамент, на котором стоит всё

В эпоху высокоуровневых абстракций, дженериков и мощных фреймворков легко забыть, что в конечном счёте любая программа — это последовательность нулей и единиц, которыми управляет процессор. **Битовые операции** — это не архаика из учебников по ассемблеру, а мощный инструмент, который:

*   Позволяет решать задачи за $O(1)$ там, где другие алгоритмы требуют $O(n)$ или дополнительной памяти.
*   Даёт прямой контроль над представлением данных в памяти, что критично для системного программирования, сетевых протоколов и работы с «железом».
*   Является излюбленной темой на технических собеседованиях: умение манипулировать битами демонстрирует глубокое понимание того, как данные хранятся и обрабатываются на уровне процессора.

В Go битовые операции представлены идиоматично и эффективно, компилируясь в нативные инструкции процессора без накладных расходов рантайма. В этой статье мы разберём не только синтаксис, но и то, как эти операции исполняются на уровне CPU, какие оптимизации применяет компилятор и как избежать типичных ловушек.

## Базовый набор операций и их семантика в Go

В языке Go поддерживаются все классические побитовые операции. Важно помнить: в отличие от некоторых языков, в Go **нет логических операторов для целых чисел** (`&&`, `||` работают только с `bool`), что исключает целый класс ошибок, связанных с неявным приведением типов.

| Операция | Обозначение в Go | Описание | Пример (8 бит) | Ассемблер (x86-64) |
|----------|-----------------|----------|----------------|-------------------|
| AND | `&` | Бит равен 1, только если оба бита равны 1 | `0b1100 & 0b1010 = 0b1000` | `AND` |
| OR | `|` | Бит равен 1, если хотя бы один бит равен 1 | `0b1100 \| 0b1010 = 0b1110` | `OR` |
| XOR | `^` | Бит равен 1, если биты различны | `0b1100 ^ 0b1010 = 0b0110` | `XOR` |
| NOT | `^` (унарный) | Инверсия всех битов (дополнение до 1) | `^0b1100 = ...11110011` | `NOT` |
| Shift Left | `<<` | Сдвиг влево (умножение на $2^n$) | `0b0011 << 2 = 0b1100` | `SHL` |
| Shift Right | `>>` | Арифметический сдвиг вправо (для знаковых) | `0b1100 >> 1 = 0b1110` (sign-extended) | `SAR` |

> [!info] Под капотом
> **Арифметический сдвиг против логического:**
> В процессорах x86 существуют две инструкции сдвига вправо: `SHR` (логический, заполняет нулями) и `SAR` (арифметический, сохраняет знаковый бит).
> В Go компилятор выбирает инструкцию на основе типа операнда:
> *   Для знаковых типов (`int`, `int8`, `int64`) используется **арифметический сдвиг** (`SAR`), чтобы сохранить знак числа.
> *   Для беззнаковых типов (`uint`, `uint32`) используется **логический сдвиг** (`SHR`).
> Это важно помнить при низкоуровневой оптимизации или при написании кода, который зависит от битового представления отрицательных чисел.

## Представление чисел: от Go-типов до машинных слов

Понимание того, как числа хранятся в памяти, критично для работы с битами.

### Знаковые числа и дополнение до двух (Two's Complement)

Go, как и подавляющее большинство современных языков и архитектур, использует **дополнение до двух** для представления знаковых целых чисел.

```go
// Пример: представление числа -5 в int8
// 1. Берем 5:      0000 0101
// 2. Инвертируем:  1111 1010
// 3. Добавляем 1:  1111 1011  <- это и есть -5

val := int8(-5)
fmt.Printf("%08b\n", val) // Вывод: -1111011 (fmt добавляет знак)
// Чтобы увидеть "сырые" биты, нужно привести к unsigned:
fmt.Printf("%08b\n", uint8(val)) // Вывод: 11111011
```

> [!warning] Ловушка / Gotcha
> **Сдвиг отрицательных чисел**
> Поведение сдвига отрицательных чисел вправо (`>>`) может быть неочевидным.
> ```go
> var x int8 = -8 // 1111 1000
> y := x >> 1     // 1111 1100 -> это -4 (округление в "минус бесконечность")
> ```
> Арифметический сдвиг сохраняет знак, заполняя старшие биты единицами. Если вам нужен логический сдвиг (заполнение нулями) для знакового типа, сначала приведите его к беззнаковому: `uint8(x) >> 1`.

### Размерность типов и переносимость

В Go размер типов `int` и `uint` зависит от архитектуры (32 или 64 бита). Это **критически важно** для битовых операций, особенно при работе с масками и сдвигами.

```go
// Опасный код:
// Если мы хотим создать маску для старшего бита:
// var mask int = 1 << 63 
// На 32-битной системе это переполнение или неопределенное поведение (в зависимости от контекста)!

// Безопасный и идиоматичный подход:
// Явно указывайте размерность, если она важна для битовой логики
var mask int64 = 1 << 63 
// Или используйте константы из math
import "math"
const MaxBit = 1 << (math.MaxInt64) // (упрощенно)
```

> [!tip] Собеседование
> **Вопрос:** В чем разница между `^x` (побитовое НЕ) и `-x` (арифметическое отрицание) для целого числа?
> **Ответ:** `^x` инвертирует биты (дополнение до 1), а `-x` в представлении Two's Complement эквивалентно `^x + 1`.
> То есть: `-5 == ^4`. Это знание часто используется в хаках для ускорения вычислений или в задачах на нахождение противоположного числа без использования оператора минуса.

## Частые паттерны и «хаки» (Bit Twiddling Hacks)

Знание этих паттернов позволяет писать код, который работает быстрее и занимает меньше места.

### 1. Проверка на степень двойки
Число является степенью двойки, если в его двоичной записи ровно одна единица.
```go
func isPowerOfTwo(n int) bool {
    // n > 0 обязательна, иначе для 0 условие (0 & -1) даст ложный результат
    return n > 0 && (n & (n - 1)) == 0
}
```
**Механика:** Если `n = 1000...0`, то `n-1 = 0111...1`. При побитовом `AND` все биты обнуляются.

### 2. Удаление младшей установленной единицы
Полезно для подсчета количества единиц (Population Count) или перебора подмножеств.
```go
// n = 110100 -> n & (n-1) = 110100 & 110011 = 110000
n = n & (n - 1)
```

### 3. XOR-трюки
Операция `XOR` обладает свойствами: `a ^ a = 0`, `a ^ 0 = a`, коммутативность.
*   **Поменять значения переменных местами без третьей:**
    ```go
    a ^= b
    b ^= a
    a ^= b
    ```
    > [!warning] Ловушка / Gotcha
    > В Go этот трюк работает, но **не рекомендуется** к использованию в продакшене. Он не дает выигрыша в производительности на современных компиляторах (они оптимизируют стандартный свап через регистры), но сильно снижает читаемость. Используйте стандартный кортежный присваивание: `a, b = b, a`.

*   **Найти уникальное число в массиве, где все остальные парные:**
    См. статью [[3. Single Number]].

### 4. Маскирование и извлечение битов
Часто требуется достать конкретный диапазон битов из "упакованного" целого числа (например, в сетевых протоколах или для хранения флагов).
```go
// Допустим, у нас есть 32-битное число, где:
// биты 0-11: идентификатор
// биты 12-15: тип сообщения
// биты 16-31: таймстемп

const (
    IDMask   uint32 = 0xFFF       // 12 бит единиц
    TypeMask uint32 = 0xF << 12   // 4 бита, сдвинутые на 12
)

func extractType(packet uint32) uint8 {
    // 1. Обнуляем лишние биты через AND
    // 2. Сдвигаем результат вправо, чтобы выровнять по младшему разряду
    return uint8((packet & TypeMask) >> 12)
}
```

## Mechanical Sympathy: Битовые операции на уровне железа

Почему битовые операции считаются «быстрыми»?

1.  **Однотактные инструкции:** На большинстве современных CPU инструкции `AND`, `OR`, `XOR`, `NOT`, `SHL`, `SHR` выполняются за 1 такт (или имеют пропускную способность 0.25-0.5 цикла на порт исполнения).
2.  **Отсутствие зависимостей по памяти:** В отличие от операций с массивами, битовые манипуляции с регистрами не требуют обращения к RAM, не создают промахов кэша (cache misses) и не нагружают шину памяти.
3.  **Предсказуемость для CPU:** Эти инструкции не меняют поток выполнения (нет условных переходов, если вы не используете результат в `if`), что позволяет конвейеру процессора (pipeline) работать на полную мощность без сбросов (flushes) из-за неверного предсказания ветвлений.

> [!info] Под капотом
> **POPCNT и BMI инструкции**
> Если вы считаете количество установленных битов (`bits.OnesCount`), компилятор Go (начиная с версий ~1.9+) при наличии поддержки в процессоре сгенерирует инструкцию `POPCNT`. Это специализированная аппаратная инструкция, которая считает единицы за несколько тактов, независимо от размера числа.
> Проверить, какие инструкции доступны, можно через `go doc cpu`.
> ```go
> import "golang.org/x/sys/cpu"
> if cpu.X86.HasPOPCNT {
>     // Используем оптимизированный путь
> }
> ```
> Всегда проверяйте реализацию в стандартной библиотеке (`math/bits`) перед тем, как писать свою реализацию подсчета битов — она, скорее всего, уже оптимальна.

## Оптимизация производительности: когда биты помогают, а когда мешают

### 1. Упаковка данных (Struct Packing)
В высоконагруженных системах (High Load) экономия памяти критична. Упаковка нескольких булевых флагов в один `uint8` или `uint32` позволяет:
*   Уменьшить потребление памяти (в 8-32 раза для флагов).
*   Улучшить утилизацию кэш-линий (в одну кэш-линию 64 байта поместится больше объектов).
*   Снизить давление на Garbage Collector (меньше аллокаций, меньше объектов для сканирования).

```go
// Плохо: каждый bool в структуре обычно занимает минимум 1 байт (а часто больше из-за выравнивания)
type RequestFlags struct {
    IsAuth   bool
    IsAdmin  bool
    IsDebug  bool
    // ... еще 5 флагов
    // Итого: минимум 8 байт + возможные паддинги до 8/16 байт
}

// Хорошо: упаковка в битовое поле
type RequestFlagsCompact uint8

const (
    FlagAuth RequestFlagsCompact = 1 << iota
    FlagAdmin
    FlagDebug
    // ...
)

func (r RequestFlagsCompact) IsAdmin() bool {
    return (r & FlagAdmin) != 0
}
```

> [!warning] Ловушка / Gotcha
> **Атомарность битовых операций**
> Если вы используете битовые флаги в многопоточной среде, обычная операция `flags |= FlagAdmin` **НЕ атомарна**. Она состоит из чтения, модификации и записи (Read-Modify-Write).
> Для безопасного изменения битов в разделяемой памяти нужно использовать `sync/atomic`:
> ```go
> import "sync/atomic"
> // Правильно:
> atomic.OrUint32(&flags, FlagAdmin) // Go 1.19+
> // Или через CAS для старых версий:
> for {
>     old := atomic.LoadUint32(&flags)
>     new := old | FlagAdmin
>     if atomic.CompareAndSwapUint32(&flags, old, new) {
>         break
>     }
> }
> ```

### 2. Битовые операции против арифметики
Иногда битовые сдвиги используют для умножения/деления на степени двойки (`x << 1` вместо `x * 2`).
**Стоит ли так делать в Go?**
В 99.9% случаев — **нет**.
Современный компилятор Го (`gc`) выполняет **Strength Reduction**: он сам заменяет умножение на константу-степень-двойки на сдвиг, если это выгодно для целевой архитектуры.
Более того, ручное использование сдвигов может сделать код менее читаемым и помешать компилятору применить другие, более сложные оптимизации. Пишите `x * 2`, доверяйте компилятору.

## Подготовка к собеседованию: типичные вопросы

1.  **Посчитать количество единичных битов (Hamming Weight).**
    *   *Решение:* Использовать трюк `n = n & (n-1)` в цикле (сложность $O(\text{число единиц})$) или встроенную функцию `bits.OnesCount`.
2.  **Поменять местами биты в числе (Reverse Bits).**
    *   *Решение:* Цикл со сдвигами или использование "магических констант" для параллельного обмена групп битов (divide and conquer).
3.  **Найти пропущенное число в массиве от 0 до N.**
    *   *Решение:* Использовать свойство `XOR`: если проксировать `XOR` всех индексов и всех значений массива, парные числа сократятся, и останется пропущенное. Это решение $O(N)$ по времени и $O(1)$ по памяти, что оптимально.
4.  **Реализовать сложение без оператора `+`.**
    *   *Решение:* Сумма без учета переноса — это `XOR`. Перенос — это `AND << 1`. Повторять итеративно, пока перенос не станет 0.

> [!tip] Собеседование
> **Вопрос:** Почему в задаче "сложить два числа без +" решение содой сходится? Не уйдем ли мы в бесконечный цикл?
> **Ответ:** На каждом шаге бит переноса (`carry`) сдвигается влево (`<< 1`). Поскольку тип данных имеет фиксированную разрядность (например, 32 или 64 бита), рано или поздно перенос либо "упадет" в старший бит и исчезнет (при арифметике по модулю $2^{32}$), либо сложение завершится. Количество итераций ограничено разрядностью сетки (максимум 32 или 64 шага).

## Практический пример: Реализация Bloom Filter

Битовые операции лежат в основе вероятностных структур данных. Рассмотрим упрощенную реализацию **Bloom Filter** — структуры для проверки принадлежности элемента множеству.

```go
package bloom

// SimpleBloom простейший фильтр Блума на одном массиве бит
type SimpleBloom struct {
    bits []uint64 // Массив "слов" по 64 бита
    size int      // Общее количество бит
}

// NewSimpleBloom создает фильтр нужного размера
func NewSimpleBloom(bitsCount int) *SimpleBloom {
    // Выделяем память с округлением вверх до 64 бит
    return &SimpleBloom{
        bits: make([]uint64, (bitsCount+63)/64),
        size: bitsCount,
    }
}

// setBit устанавливает бит по индексу в 1
func (b *SimpleBloom) setBit(index int) {
    if index < 0 || index >= b.size {
        return
    }
    // 1. Находим индекс "слова" в массиве (целочисленное деление на 64)
    wordIdx := index >> 6 // эквивалент index / 64, но быстрее
    
    // 2. Находим смещение бита внутри слова (остаток от деления)
    bitIdx := index & 63  // эквивалент index % 64, но быстрее (маска)
    
    // 3. Устанавливаем бит через побитовое ИЛИ
    b.bits[wordIdx] |= (1 << bitIdx)
}

// getBit проверяет, установлен ли бит
func (b *SimpleBloom) getBit(index int) bool {
    if index < 0 || index >= b.size {
        return false
    }
    wordIdx := index >> 6
    bitIdx := index & 63
    // Проверяем бит через побитовое И и сравнение с 0
    return (b.bits[wordIdx] & (1 << bitIdx)) != 0
}
```

> [!info] Под капотом
> Обратите внимание на замену деления и взятия остатка на сдвиги и маски:
> *   `index / 64` → `index >> 6`
> *   `index % 64` → `index & 63`
> Хотя компилятор часто делает это сам (т.к. 64 — степень двойки), в низкоуровневых алгоритмах, выполняемых миллионы раз (как в базе данных), явное использование битовых операций сигнализирует о намерениях разработчика и гарантирует генерацию оптимального кода даже при агрессивных оптимизациях.

## Итог

1.  **Битовые операции** — это прямой мост к возможностям процессора. Они быстры, детерминированы и предсказуемы.
2.  В Go используйте их для **оптимизации памяти** (флаги, компактные структуры) и **решения специфических алгоритмических задач** (хэширование, криптография, сетевые пакеты).
3.  **Не злоупотребляйте**: не заменяйте арифметику на сдвиги ради "микро-оптимизаций" в бизнес-логике — компилятор умнее, а читаемость кода важнее.
4.  Помните про **потокобезопасность**: битовые флаги в конкурентной среде требуют `atomic` операций.
5.  Знание трюков с `XOR`, масками и сдвигами — отличный способ блеснуть на алгоритмическом интервью, демонстрируя понимание фундаментальной информатики.
